SISTEMAS DISTRIBUIDOS · PRUEBA DE FUEGO

Tres backends.
Un líder. Quorum 2/3.

Los navegadores son clientes WebSocket. El estado autoritativo se replica y fuerza a disco en tres procesos Node; ningún celular ejecuta el motor cuando cae un servidor.

Topología

flowchart LR
  C[Celulares] <-->|WebSocket| N1[Backend 1]
  M[Master] <-->|WebSocket| N2[Backend 2]
  N1 <-->|N2N| N2
  N2 <-->|N2N| N3[Backend 3]
  N1 <-->|N2N| N3
  N1 --> D1[(disco 1)]
  N2 --> D2[(disco 2)]
  N3 --> D3[(disco 3)]

Commit de una jugada

sequenceDiagram

  participant L as Líder
  participant R2 as Réplica 2
  participant R3 as Réplica 3
  C->>L: acción + actionId + stateVersion + Lamport
  L->>L: mutex FIFO + fsync
  L->>R2: N_REPLICATE
  L->>R3: N_REPLICATE
  R2-->>L: ACK durable
  L-->>C: broadcast confirmado 2/3

Caída del líder

sequenceDiagram
  participant L as Líder caído
  participant R2 as Réplica 2

  participant C as Cliente
  Note over L: sin heartbeat durante 2000 ms
