Gestión para la Verificación y Validación del Software
1. Objetivo General
Implementar un proceso integral de verificación y validación para evaluar la calidad, seguridad,
mantenibilidad, confiabilidad y rendimiento de un sistema distribuido.
2. Objetivos Específicos
• Analizar la calidad del código mediante SonarQube.
• Configurar pipelines de integración continua utilizando Jenkins.
• Automatizar pruebas funcionales utilizando Selenium o Cypress.
• Realizar pruebas de seguridad utilizando Burp Suite.
• Validar concurrencia, sincronización y tolerancia a fallos.
• Documentar métricas, hallazgos y propuestas de mejora continua.
3. Alcance del Proyecto
• El sistema deberá incluir al menos un frontend o interfaz de interacción.
• El proyecto deberá permitir la aplicación de pruebas funcionales, pruebas técnicas y
validaciones de seguridad.
4. Componentes Obligatorios del Proyecto de V&V
4.1 Calidad de Código con SonarQube
• Configuración de análisis automático del proyecto.
• Detección de bugs, vulnerabilidades y code smells.
• Análisis de complejidad ciclomática y duplicación de código.
• Generación de métricas de calidad técnica.
4.2 Integración Continua con Jenkins
• Construcción automática del sistema.
• Ejecución automática de pruebas.
• Integración automática con SonarQube.
• Ejecución del pipeline por cada commit realizado.
4.3 Pruebas Automatizadas con Selenium o Cypress
• Automatización de casos funcionales del sistema.
• Validación de flujos de usuario.
• Pruebas de interfaz y comportamiento en tiempo real.
• Pruebas concurrentes y de interacción distribuida.
• Generación de evidencias y reportes de ejecución.
4.4 Pruebas de Seguridad con Burp Suite
• Análisis de tráfico HTTP, WebSockets o protocolos utilizados.
• Manipulación de mensajes y validación de entradas.
• Pruebas de spoofing, replay attacks y flooding.
• Validación de autenticación y control de acceso.
• Análisis de robustez y resiliencia del sistema distribuido.
4.5 Validación Distribuida
• Validación de sincronización entre nodos.
• Pruebas de concurrencia.
• Validación de consistencia de datos.
• Medición de latencia y tiempos de respuesta.
• Pruebas de tolerancia a fallos y recuperación.
5. Documentación Requerida
• Plan de Verificación y Validación.
• Matriz de trazabilidad.
• Reporte técnico final.
• Resultados de pruebas y métricas obtenidas.
• Evidencias visuales y capturas del sistema.
6. Entregables y Evaluación
Entregable Porcentaje
Configuración y análisis SonarQube 20%
Pipeline Jenkins 20%
Pruebas Automatizadas 25%
Pruebas de Seguridad 20%
Documentación Técnica 15%
8. Resultado Esperado
Al finalizar el semestre, los estudiantes deberán presentar un sistema distribuido funcional
acompañado de un proceso completo de aseguramiento de calidad, integración continua,
automatización de pruebas y validación de seguridad basado en herramientas modernas de la
industria.
